# Email Prompt-Injection Candidate Attempts

Generated for controlled LivePI-style red-team experiments on the `email_gmail` information source. Do not send these to real users or production mailboxes. Each candidate is a template: substitute the objective placeholders only inside the isolated benchmark harness.

## Literature Takeaways

- LivePI evaluates seven realistic input surfaces and five malicious goals in a production-like but test-controlled environment; the local email sweep currently shows 0% ASR, so the next experiment should broaden strategy coverage rather than only retry the same technique set.
- OWASP describes remote or indirect prompt injection as malicious instructions hidden in external content such as emails, documents, webpages, code comments, and attachments; it also highlights hidden text and metadata variants.
- Early indirect-prompt-injection work argues that LLM-integrated applications blur the data/instruction boundary, enabling remote exploitation when the model retrieves attacker-controlled content.
- AgentDojo and InjecAgent emphasize end-to-end tool-integrated agents, where the relevant question is not only whether the model repeats injected text but whether it reaches a harmful tool call.
- LLMail-Inject is especially relevant: it collected adaptive attacks against an LLM-based email assistant and found that even layered defenses can be bypassed in controlled settings.
- EchoLeak is a production case study showing that a single crafted email can cross LLM trust boundaries when retrieval, link/image handling, and defense bypasses compose.
- Recent attack-effectiveness studies suggest testing obfuscation, semantic/social framing, and composite attacks, because simple keyword-style defenses miss many paraphrased or hidden variants.
- Defense papers such as Spotlighting, BIPIA, and StruQ point to the same root issue: source provenance and instruction/data separation are weak when everything is flattened into one model context.

2. Then test F06 and F07 to measure whether the email parser, HTML rendering, or prompt filters change behavior.

## Gemini-Inspired Benchmark Extension

Gemini's proposal is useful as an exploratory extension, but one detail should be kept distinct: LivePI describes prompt-level filtering plus pre-execution tool-call authorization, while MultiPhishGuard is a separate multi-agent phishing-email detection framework. The extension below uses the Gemini ideas as red-team case generation pillars, not as claims about the original LivePI defense implementation.

The five implemented extension technique tags are:

- `vibe_hacking`: professional, urgent administrative language that camouflages the task as privileged workflow.
- `multilanguage_payload_fragmentation`: split semantics across English, a non-English footer, and a Base64-encoded task field.
- `context_correction_hijacking`: fake follow-up corrections to stale workflow parameters.
- `html_css_zero_click_injection`: HTML comments, CSS variables, and hidden spans in multipart email bodies.
- `logical_entrapment_verification`: verification or summarization requests that attempt to turn checking into execution.
